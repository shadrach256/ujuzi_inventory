1. Project Overview

The Ujuzi Inventory Management System is a full-stack web application built with the Laravel PHP framework. It allows a business to keep track of its products, stock quantities, and inventory value in one place.

Key Features

  • User Authentication — register, log in, and log out securely.
  • Product Management (CRUD) — create, read, update, and delete products.
  • Image Uploads — attach a product photo when creating or editing.
  • Stock Tracking — "stock in" and "stock out" buttons to adjust quantities.
  • Low Stock Alerts — highlights products with 5 or fewer units left.
  • Role-Based Dashboards — regular users see a simple product list; admins see KPIs and charts.
  • Analytics (Admin only) — total products, total units, inventory value, and Chart.js graphs.

Who Uses It?

RoleWhat they can do
UserLog in, view products, add/edit/delete products, adjust stock.
AdminEverything a user can do, plus see KPI cards and inventory charts.

3. MVC Architecture

Laravel follows the Model-View-Controller (MVC) pattern. This separates the app into three parts:

  • Model — talks to the database. Represents a table (e.g., Product = the products table).
  • View — the HTML the user sees. In Laravel these are .blade.php files.
  • Controller — the "middleman" that receives a request, asks the Model for data, and passes it to a View.

How a Request Flows

Browser URL → Route (routes/web.php) → Middleware (auth/admin) → Controller → Model (DB) → View (HTML) → Browser

Example: Visiting the Dashboard

  1. User visits /dashboard.
  2. The route file matches this URL to ProductController@index.
  3. The auth middleware checks the user is logged in.
  4. The controller asks the Product model for all products.
  5. The controller passes the products to the dashboard.blade.php view.
  6. The view renders HTML, which the browser displays.

4. Database Design & Migrations

Laravel uses migrations to define the database schema in code. This means the database structure is version-controlled and can be recreated anywhere with one command: php artisan migrate.

4.1 The users Table

Created by database/migrations/0001_01_01_000000_create_users_table.php:

Schema::create('users', function (Blueprint $table) {
    $table->id();
    $table->string('name');
    $table->string('email')->unique();
    $table->timestamp('email_verified_at')->nullable();
    $table->string('password');
    $table->rememberToken();
    $table->timestamps();
});
ColumnPurpose
idUnique number for each user.
nameThe user's display name.
emailLogin email (must be unique).
passwordHashed password (never stored in plain text).
typeAdded later — either 'user' or 'admin'.

4.2 Adding the type Column (Role System)

To support user vs admin roles, we added a type column with a migration (2026_08_10_095021_add_type_to_users_table.php). New users default to 'user': 

public function up(): void
{
    Schema::table('users', function (Blueprint $table) {
        $table->string('type')->default('user');
    });
}

public function down(): void
{
    Schema::table('users', function (Blueprint $table) {
        $table->dropColumn('type');
    });
}
How roles are changed: There is no in-app button to change roles. Instead, an admin opens the database (e.g., phpMyAdmin at localhost/phpmyadmin), finds the users table, and edits the type column from user to admin. The change takes effect the next time that user logs in.

4.3 The products Table

All web routes live in routes/web.php. A route maps a URL + HTTP method to a controller method (or a closure). Here is the full route list:

6. Controllers

Controllers contain the application logic. They receive requests, interact with models, and return views.

6.1 ProductController — app/Http/Controllers/ProductController.php

index() — Show the user dashboard

public function index()
{
    $products = Product::all();

    $lowStockThreshold = 5;
    $lowStockProducts = $products->where('quantity', '<=', $lowStockThreshold);

    return view('dashboard', compact('products', 'lowStockProducts'));
}

Gets all products, finds any with 5 or fewer units (low stock), and passes both to the dashboard view.

store() — Save a new product (with image upload)

public function store(Request $request)
{
    $data = $request->validate([
        'name' => 'required',
        'sku' => 'required|unique:products',
        'price' => 'required|numeric',
        'quantity' => 'required|integer',
        'image' => 'nullable|image|mimes:jpeg,png,jpg,gif,webp|max:2048',
    ]);

    if ($request->hasFile('image')) {
        $path = $request->file('image')->store('products', 'public');
        $data['image'] = $path;
    }

    Product::create($data);

    return redirect('/dashboard')->with('success', 'Product added!');
}

Validates the form data, uploads the image to the public disk if provided, creates the product, and redirects back to the dashboard with a success message.

update() — Edit an existing product

public function update(Request $request, Product $product)
{
    $data = $request->validate([
        'name' => 'required',
        'sku' => 'required|unique:products,sku,'.$product->id,
        'price' => 'required|numeric',
        'quantity' => 'required|integer',
        'image' => 'nullable|image|mimes:jpeg,png,jpg,gif,webp|max:2048',
    ]);

    if ($request->hasFile('image')) {
        $path = $request->file('image')->store('products', 'public');
        $data['image'] = $path;
    }

    $product->update($data);

    return redirect('/dashboard')->with('success', 'Product updated!');
}

Similar to store, but updates an existing product. Note the SKU validation ignores the current product's own SKU (unique:products,sku,{id}).

destroy() — Delete a product

public function destroy(Product $product)
{
    $product->delete();
    return redirect('/dashboard')->with('success', 'Product deleted!');
}

stockIn() / stockOut() — Adjust stock

public function stockIn(Request $request, $id)
{
    $product = Product::findOrFail($id);
    $product->quantity += $request->quantity;
    $product->save();
    return redirect('/dashboard')->with('success', 'Stock added!');
}

public function stockOut(Request $request, $id)
{
    $product = Product::findOrFail($id);
    $product->quantity -= $request->quantity;
    $product->save();
    return redirect('/dashboard')->with('success', 'Stock removed!');
}

These add or subtract from a product's quantity. findOrFail returns a 404 if the product doesn't exist.

6.2 AdminController — app/Http/Controllers/AdminController.php

public function dashboard()
{
    $products = Product::all();

    $totalProducts = $products->count();
    $totalUnits = $products->sum('quantity');
    $inventoryValue = $products->sum(fn ($product) => $product->price * $product->quantity);
    $lowStockThreshold = 5;
    $lowStockCount = $products->where('quantity', '<=', $lowStockThreshold)->count();
    $lowStockProducts = $products->where('quantity', '<=', $lowStockThreshold);

    return view('admin.dashboard', compact(
        'products', 'totalProducts', 'totalUnits',
        'inventoryValue', 'lowStockCount', 'lowStockProducts',
    ));
}

The admin dashboard computes extra analytics: total products, total units, total inventory value (price × quantity summed), and low-stock counts. These feed the KPI cards and charts.

7. Models

Models represent database tables and provide an object-oriented way to query them.

7.1 User — app/Models/User.php

class User extends Authenticatable
{
    use HasFactory, Notifiable;

    protected $fillable = [
        'name', 'email', 'password', 'type',
    ];

    protected $hidden = [
        'password', 'remember_token',
    ];

    public function isAdmin(): bool
    {
        return $this->type === 'admin';
    }
}
  • $fillable — which columns can be mass-assigned (safety feature).
  • $hidden — hides the password and remember token from JSON responses.
  • isAdmin() — a helper that returns true if the user's type is 'admin'.

7.2 Product — app/Models/Product.php

class Product extends Model
{
    protected $fillable = [
        'name', 'sku', 'image', 'price', 'quantity',
    ];
}

A simple model. The $fillable array must include image so image uploads can be saved.

8. Middleware & the Role System

Middleware runs before a request reaches a controller. It's like a security guard at the door.

8.1 EnsureUserIsAdmin — app/Http/Middleware/EnsureUserIsAdmin.php

class EnsureUserIsAdmin
{
    public function handle(Request $request, Closure $next): Response
    {
        if (! $request->user()?->isAdmin()) {
            return redirect('/dashboard');
        }

        return $next($request);
    }
}

If the logged-in user is not an admin, they are redirected to the regular dashboard. Otherwise, the request continues ($next($request)).

8.2 Registering the Middleware — bootstrap/app.php

->withMiddleware(function (Middleware $middleware): void {
    $middleware->alias([
        'admin' => EnsureUserIsAdmin::class,
    ]);
})

This gives the middleware a short alias, admin, so we can use it in routes like Route::middleware(['auth', 'admin']).

8.3 How the Role System Works End-to-End

User signs up → type = 'user' (default) → Admin edits DB in phpMyAdmin → type = 'admin' → User logs in again → Redirected to /admin/dashboard

The login route checks Auth::user()->isAdmin() to decide where to redirect. The admin middleware protects the admin dashboard from non-admins.

10.3 How Tests Use Factories

database/factories/UserFactory.php generates test users. It has an admin() state so tests can easily create an admin: 

public function definition(): array
{
    return [
        'name' => fake()->name(),
        'email' => fake()->unique()->safeEmail(),
        'password' => static::$password ??= Hash::make('password'),
        'type' => 'user',
    ];
}

public function admin(): static
{
    return $this->state(fn (array $attributes) => [
        'type' => 'admin',
    ]);
}

Tests use RefreshDatabase so each test starts with a clean database, and User::factory()->admin()->create() creates an admin user for testing.

11. How to Run the Project

These are the commands to set up and start the app on a local machine (e.g., XAMPP):

# 1. Install PHP dependencies
composer install

# 2. Install JavaScript dependencies
npm install

# 3. Copy environment file and set your database credentials in .env
cp .env.example .env
php artisan key:generate

# 4. Create the database tables
php artisan migrate

# 5. Build frontend assets
npm run build

# 6. Start the development server
php artisan serve
# Then visit http://127.0.0.1:8000
To make someone an admin: After registering a user, open phpMyAdmin (http://localhost/phpmyadmin), open the users table, and change that user's type from user to admin.

12. Presenter's Cheat Sheet

Simple talking points you can say aloud, in plain English:

What is the project?

"This is an inventory management web app. It lets a business register users, log in, and manage their products — adding items, tracking stock, and seeing how much inventory is worth."

What framework and why?

"It's built with Laravel, a popular PHP framework. Laravel gives us authentication, database migrations, and a clean structure out of the box, so we don't have to build everything from scratch."

How is it structured? (MVC)

"It follows the Model-View-Controller pattern. Models talk to the database, Views are the HTML pages, and Controllers handle the logic in between. When you visit a page, a route sends the request to a controller, which gets data from a model and passes it to a view."

How does the database work?

"We have two main tables: users and products. We use Laravel migrations to define the tables in code, so the database can be recreated anywhere. We added a 'type' column to users to support admin and regular user roles."

How do roles work?

"When someone signs up, they're a regular user by default. To make someone an admin, you change their 'type' to 'admin' directly in the database, for example in phpMyAdmin. The next time they log in, they get admin access and see the admin dashboard with KPIs and charts."

What can users do?

"Users can add, edit, and delete products, upload product images, and adjust stock with 'stock in' and 'stock out' buttons. They also see low-stock alerts."

What can admins do that users can't?

"Admins see the full analytics dashboard — KPI cards showing total products, total units, inventory value, and low-stock items, plus charts. Regular users just see the product list."

How is security handled?

"Passwords are hashed, so they're never stored in plain text. We use middleware to protect routes — you must be logged in to access the app, and you must be an admin to access admin pages. We also validate all form input."

How is it tested?

"We have 12 automated tests that verify products can be created, updated, and deleted, and that the role system works — regular users can't access admin pages, admins can, and new users default to the 'user' role."
